- `RetryConfig` adds `max_server_delay` (default 60 seconds), separate from the exponential `max_delay`. Server hints within the limit are honored in full; larger hints return the original error immediately instead of shortening its delay. Struct literals must supply the new field or use `..RetryConfig::default()`. `Retry-After` delay-seconds now follow the RFC integer grammar; fractional, signed, and overflowing values are ignored. HTTP 520–524 are retryable. `execute_with_retry_observer` offers a cancellable notification before the existing executor sleeps or retries.
