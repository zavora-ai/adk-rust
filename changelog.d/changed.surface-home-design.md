- adk-surface: the web home's visual language is "calm mission control" (spec 3.3 §9). It uses Geist and Geist Mono over warm neutrals, keeps one accent for what waits on the person and for the primary action, and has a layered near-black dark theme. Its foundations are a seven-step type scale, three radii, two-layer shadows and 120/160/240 ms motion that respects reduced motion. The tokens are written by a script that checks WCAG AA contrast.
- adk-surface: the developer panel opens on **Run**: the graph of who hands work to whom, the tree of every step and the trace of those steps on one clock, with an inspector for whatever is picked in any of them. It reads the session's trace spans and, while a run waits, its events, so a call held for the person shows as held. It replaces the Topology and Telemetry tabs.
- adk-surface: the voice view shows realtime talk and vision as they happen. A presence follows the real loudness of the mic and of the model's voice. Captions show what it heard and when the person spoke over it, and a spoken "allow once" counts down on a ring. "What it can see" shows the live camera or screen and the last frames sent to the model; a frame's thumbnail goes when its source turns off. The mic, camera, screen and End controls sit in a call dock, as round buttons on a phone.
- adk-surface: a person can send images with a message (spec 3.3 §5.1). `send`, `queue` and `newThread` carry up to four PNG, JPEG, WebP or GIF images. The engine checks each image's bytes before the images reach the agent as parts of the message. The web home's message box takes images that are picked, pasted or dropped, and the thread shows them. A message with images waits for the next turn instead of steering the running one. Sources gain `start_turn_images` and `start_turn_with_images`, which have defaults; `Harness::send_content_as` sends a whole message.
- adk-surface: a command an agent ran, or code it ran in the sandbox, reads as a run (`ThreadItem::Run`). It shows what ran, how it exited or why it stopped short, how long it took, its last lines and where it ran. Roster rows say where each agent's commands run (`AgentRow.shell`), from the harness's isolation: the OS sandbox and its enforcer, a container, a remote sandbox, this computer, or a sandbox that is unavailable.
- adk-surface: the web home has a command palette, opened with ⌘K or Ctrl+K or with **Search** in the header. It finds sections, agents' threads, decisions waiting for you and actions. It opens a decision's card and never answers one. Three or more tool steps in a row fold into one work-log line. Each screen of the example is checked with axe at WCAG 2.1 AA in light and dark (`e2e/a11y.spec.ts`).
- adk-surface: on a wide screen the web home's sections are an icon rail down the left edge, with Developer at its foot. **Show beside** keeps a drawing in a canvas next to the thread, with tabs for its latest version, its earlier versions and its A2UI. A waiting decision leads with its question and what it costs, then who asks and the exact call.
