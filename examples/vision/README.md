# vision

Scenarios S1–S19 of spec 3.7 §5 for `adk-vision`: the Document desk and the rest of phase A
(S1–S8); phase B's Inspector, visual wakes, frame budgets, live camera surface and native video
(S9–S13); phase C's Screen copilot, Inspector as a team, visual memory and video analyst
(S14–S17); face blur on streams and the on-device profile (S18, S19). Every pass condition is
asserted on egress records, audit records, approvals, the spend ledger, the frame governor's
steps, stored frames, vector stores, memories, the pixels that left and what reached a browser
or a desktop, never on model prose.

| Runs | How |
|------|-----|
| On the device | PP-OCRv6 tiny reads, RF-DETR Nano detects people and YuNet faces, SAM 2.1 Tiny q4 segments, SigLIP 2 base embeds images and text, fetched by revision through the model fetcher and checked by SHA-256 on the first run |
| Streams | The conveyor clip (`adk_vision::stream::fixtures::ConveyorClip`) over the in-process RTSP server into the stream pipeline; the kernel, the harness and the live camera surface in process |
| In a sandbox | S19 runs this binary again under Seatbelt (macOS) or bubblewrap (Linux, `bwrap` installed and unprivileged user namespaces allowed) with the network denied |
| In the cloud | NVIDIA NIM, Claude, Gemini and Meta `sam-3.1` answer from recorded responses (`fixtures/recorded/`, and S17 from adk-vision's own), served to their real clients from a local server, so no key is needed; S15's two answers are scripted in each provider's wire format |
| On a screen | S14's CRM is served in process over HTTP and read through `adk-browser`'s tools from a stand-in WebDriver server (`src/crm.rs`); its desktop is a stand-in display at device pixel ratio 2 whose form app draws what it is typed (`src/screen.rs`), read by PP-OCRv6 tiny and acted on only through the computer-use pack's governed graph |
| The agent | A harness with the vision pack on a scripted planner |

```bash
cargo run                                   # every scenario, then a pass table
cargo run -- s3_redact_before_it_leaves     # one scenario
cargo run -- --report vision-scenarios.md   # the table as Markdown
```

The first run downloads about 545 MB of weights into the Hugging Face cache (SigLIP 2 base
quantized, for S16, is 381 MB of it, and YuNet 232 KB); set `HF_HUB_CACHE` to keep them
elsewhere. CI caches them. `VISION_STREAM_SPEED` sets how
fast the RTSP scenarios play the clip (twice real time by default). No ffmpeg is needed: S11's
clips are committed, and S13 draws its frames from the clip's sprites when there is no ffmpeg.
