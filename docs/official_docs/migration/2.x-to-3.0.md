# Migrating from ADK-Rust 2.x to 3.0

3.0.0 is a major release. This guide lists the breaking changes between the published 2.3.0
crates and 3.0.0: the API breaks, which were checked with `cargo semver-checks check-release`
against 2.3.0, and the behaviour changes that need a code change or a decision. The
[CHANGELOG](../../../CHANGELOG.md) has the full entry for each, and the SQLx 0.9 upgrade has its
own guide, [SQLx 0.9 in ADK-Rust 3.0](sqlx-0.9.md).

Update every `adk-*` dependency together — the crates are versioned in lockstep:

```toml
[dependencies]
adk-rust = { version = "3.0.0", features = ["standard"] }
```

## Quick reference

| If your code… | Do this |
|---|---|
| builds `RunConfig`, `EventActions`, `LlmResponse` or another config struct with a literal | end the literal with `..Default::default()` or use the constructor ([struct literals](#struct-literals)) |
| builds `RunnerConfig` with a literal | use `Runner::builder()` |
| matches exhaustively on `ErrorCategory`, `GraphError`, `GuardrailError`, an `adk-anthropic` enum, or another enum in the [table](#exhaustive-matches) | add the new arms |
| relies on a tool being retried | declare `ToolEffect::Idempotent` or `ReadOnly` ([retries](#tool-retries-follow-the-declared-effect)) |
| reads the error text the model receives for a failed tool | call `expose_tool_error_messages(true)` ([tool errors](#tool-failures-reach-the-model-without-their-message)) |
| builds `tool_confirmation_fingerprints` with `tool_call_fingerprint` | take `fingerprint()` from the held call's request ([fingerprints](#approval-fingerprints-name-the-agent-and-the-tool)) |
| wraps `Tool`, `ReadonlyContext`, or `Agent` | forward the new trait methods ([wrappers](#wrappers-forward-the-new-trait-methods)) |
| serves agents to other machines or browsers | set the bind address, `allowed_hosts`, and `allowed_origins` ([server exposure](#the-server-is-reachable-from-this-machine-only-by-default)) |
| has graph runs paused under 2.3.0 | finish them before upgrading, or re-key their checkpoints ([graph threads](#graph-checkpoints-are-keyed-by-app-user-and-session)) |
| uses `#[tool]`, `FunctionTool`, or `StatefulTool` with a schema | expect undeclared keys and out-of-range values to be rejected ([argument validation](#tool-arguments-are-checked-against-the-schema)) |
| uses `PostgresAuditSink` | call `migrate()` before the first write ([audit](#adk-auth)) |
| calls `SessionService::rewind` or `rewind_steps` | pass an `AdkIdentity` ([rewind](#adk-session)) |
| implements `PaymentPolicyGuardrail` | make `evaluate` async and add the context parameter ([payments](#adk-payments)) |
| runs `cargo adk eval` | pass `--agent-cmd` ([eval](#adk-eval-and-cargo-adk)) |

## Before you upgrade

Some changes affect state written by 2.3.0 or the way a deployment is reached. Handle these
before or during the upgrade.

| Stored state or deployment | What 3.0 does | Do this |
|---|---|---|
| Graph runs paused by `GraphAgent` or a `NodeTool` | Keys checkpoints by app, user, and session; checkpoints under a bare session id are not read | Finish paused runs on 2.3.0, or re-key them ([details](#graph-checkpoints-are-keyed-by-app-user-and-session)) |
| Runs paused inside a `SubgraphNode` or a `run_node` child | Keys child work by activation, so the child starts again on resume | Finish those runs on 2.3.0 |
| Tool calls held for confirmation | Binds approvals to the agent and the tool's origin; a call held under 2.3.0 is answered as not run when a decision resumes it | Re-issue the held calls after the upgrade |
| `PostgresAuditSink` tables | Writes the new `agent_id` and `on_behalf_of` columns | Call `migrate()` once; until then every insert fails and guarded tools are refused |
| SQLite, PostgreSQL, and MongoDB session stores | Adds migration 2 (`sessions.initial_state` on SQLite, `events.seq` on PostgreSQL, an index on MongoDB) | Call the service's `migrate()` |
| `RedisSessionService` | Writes sessions through Lua scripts | Allow `EVAL` for the service's Redis user |
| `FileArtifactService` directories | Writes a new layout for names and user-scoped artifacts; the earlier layout is still read | Update tools that read the directory tree directly |
| Artifacts saved under the session id `user` | Reserves that id for user-scoped artifacts, so those artifacts are unreachable | Copy them to another session before upgrading |
| pgvector collections | Validates collection names instead of rewriting them | Use the existing table's name without its `rag_` prefix |
| Background runs persisted by `FileRunPersistence` | Removes the file store; runs live in a `DurableRunStore` | Let persisted runs finish on 2.3.0, and re-create cron jobs |
| Servers reached from other machines or browsers | Listens on `127.0.0.1`, allows no cross-origin access, and checks the `Host` header | Configure the bind address, hosts, and origins ([details](#the-server-is-reachable-from-this-machine-only-by-default)) |

## Struct literals

Most API breaks are new public fields. A struct literal that names every field stops compiling;
one that ends with `..Default::default()`, or a constructor, keeps compiling:

```rust
use adk_core::{Content, EventActions, LlmResponse, RunConfig, StreamingMode};

let config = RunConfig { streaming_mode: StreamingMode::SSE, ..Default::default() };
let actions = EventActions { escalate: true, ..Default::default() };
let response = LlmResponse {
    content: Some(Content::new("model").with_text("Done.")),
    ..Default::default()
};
```

These enums gain variants and are not `#[non_exhaustive]`, so an exhaustive `match` needs the
new arms:

|---|---|---|
| `ErrorCategory` | `adk-core` | `ResourceExhausted` (HTTP 429), `Conflict` (HTTP 409) |
| `GraphError` | `adk-graph` | `AgentFailed`, `FanInIncomplete`, `CheckpointConflict`, `Suspended`, `Cancelled`; `DatabaseError` is removed |
| `GuardrailError` | `adk-guardrail` | `Blocked` |
| `ClientError` | `adk-gemini` | `ErrorInResponse` |
| `ContentBlock` | `adk-anthropic` | `CodeExecutionToolResult`, `BashCodeExecutionToolResult`, `TextEditorCodeExecutionToolResult`, `Unknown` |
| `ContentBlockDelta`, `MessageStreamEvent` | `adk-anthropic` | `Unknown` |
| `StopReason` | `adk-anthropic` | `Unknown(String)` |
| `ToolUnionParam` | `adk-anthropic` | `WebSearch20260209`, `WebFetch20260209` |
| `WebFetchErrorCode` | `adk-anthropic` | `UrlTooLong`, `UrlNotAccessible`, `UnsupportedContentType`; `Unknown` becomes `Unknown(String)` |
| `WebSearchErrorCode` | `adk-anthropic` | `RequestTooLarge`, `Unknown(String)` |
| `WebhookVerifyError` | `adk-anthropic` (`managed-agents`) | `MissingHeader`, `TimestampInFuture` |
| `TaskState` | `adk-server` | `AuthRequired` |
| `V1ClientError` | `adk-server` (`a2a-v1`) | `CardEndpoint`, `Credential` |
| `ServerStatus` | `adk-tool` (`mcp`) | `Starting` |

Two enums become `#[non_exhaustive]`, so a `match` on them outside their crate needs a wildcard
arm: `adk_sandbox::SandboxError` and `adk_server::background::RunStatus` (which also gains
`Waiting`).

```rust
use adk_core::{AdkError, ErrorCategory};

fn next_step(error: &AdkError) -> &'static str {
    match error.category {
        ErrorCategory::InvalidInput | ErrorCategory::Unsupported => "fix the request",
        ErrorCategory::Unauthorized | ErrorCategory::Forbidden => "check the credentials",
        ErrorCategory::NotFound => "check the id",
        ErrorCategory::RateLimited | ErrorCategory::Timeout | ErrorCategory::Unavailable => {
            "retry later"
        }
        ErrorCategory::Cancelled => "stop",
        ErrorCategory::Internal => "report a bug",
        // New in 3.0
        ErrorCategory::ResourceExhausted => "raise the budget or stop",
        ErrorCategory::Conflict => "reload and retry",
    }
}
```

## adk-core and adk-runner

### Tool retries follow the declared effect

A `RetryBudget` retried every failed call, including one that timed out after its side effect
happened. `LlmAgent` and `CodeActAgent` now retry only a tool whose `Tool::effect()` is
`ReadOnly` or `Idempotent`, and only after a retryable error or a timeout. A tool that declares
nothing and is not `is_read_only()` is `NonIdempotent` and runs once. Declare the effect to keep
retrying a tool — `#[tool(idempotent)]`, `FunctionTool::with_effect`, or `Tool::effect`:

```rust
use adk_core::ToolEffect;
use adk_tool::FunctionTool;
use serde_json::json;

let lookup = FunctionTool::new("lookup_order", "Looks up an order", |_ctx, args| async move {
    Ok(json!({ "order": args["id"] }))
})
.with_effect(ToolEffect::Idempotent);
```

The delay ceiling now doubles per retry up to `RetryBudget::max_delay` (30 seconds by default),
and each delay is drawn from the upper half of that ceiling. Build the budget with its
constructor:

```rust
use std::time::Duration;
use adk_core::RetryBudget;

// 2.3
let budget = RetryBudget { max_retries: 2, delay: Duration::from_millis(500) };
```

```rust
use std::time::Duration;
use adk_core::RetryBudget;

// 3.0
let budget = RetryBudget::new(2, Duration::from_millis(500))
    .with_max_delay(Duration::from_secs(5));
```

An `AgentTool` delegation no longer stops at the parent agent's `tool_timeout`; set
`AgentTool::timeout` to bound it. A delegation that runs past that timeout is a tool error with
`ErrorCategory::Timeout`, not an `{"error": ...}` result.

### Interrupted calls report an unknown outcome

A non-idempotent call that times out or panics, and a call still in flight when a run is
cancelled, is answered with `{"status": "outcome_unknown", ...}` instead of `{"error": ...}`, so
the model does not call it again. Code that reads function responses detects it with
`adk_core::is_outcome_unknown`.

### Approval fingerprints name the agent and the tool

`ToolConfirmationRequest::fingerprint()` now covers the acting agent's id and the tool's
origin as well as the tool name and arguments, so an approval for one agent's call does not
authorize another agent's call with the same arguments. A fingerprint built with
`tool_call_fingerprint(name, args)`, or from a request without an acting agent, matches no
call, and the call stays held; `RunConfigBuilder::tool_approval` refuses one. Take the
fingerprint from the request the held call surfaced, or build it for the agent and tool:

```rust
use adk_core::tool_call_fingerprint;

// 2.3
let fingerprint = tool_call_fingerprint(transfer.name(), &args);
```

```rust
use adk_core::{ActingContext, AgentPrincipal, ToolConfirmationRequest};

// 3.0
// From the request the held call surfaced:
let fingerprint = request.fingerprint();
// Or built for a known agent and tool:
let fingerprint = ToolConfirmationRequest::for_tool(transfer.as_ref(), args)
    .with_acting_context(ActingContext::new(AgentPrincipal::derived("ops", "treasurer")))
    .fingerprint();
```

A call held under 2.3.0 records no agent or origin, so it is answered as not run when a decision
resumes it; re-issue it.

### Held calls are answered and resumed

- Enhanced plugins, runner hooks, and `BeforeToolCallback`s run before the policy, guardrails,
  and confirmation, so an approval covers the arguments that execute, and the
  `ToolConfirmationRequest` carries them.
- A call awaiting confirmation without a handler receives `confirmation_pending_response`
  (`"status": "confirmation_pending"`), and the turn's other calls run before the run ends.
- The next run executes an approved held call under its original call ID, so the model does not
  need to issue it again.
- `SequentialAgent`, `LoopAgent`, `ParallelAgent`, `ConditionalAgent`, and
  `LlmConditionalAgent` stop at a held call and resume at the sub-agent that held it, instead of
  running their later sub-agents in the same run.
- Compaction stops before the earliest held call, so a custom `CompactionStrategy` receives
  fewer events while a call is undecided.
- A `ToolConfirmationHandler` decision that takes longer than
  `RunConfig::tool_confirmation_timeout` (five minutes by default) leaves the call waiting in
  the run's approval store, or denies it when the run has none or sets
  `RunConfig::deny_on_confirmation_timeout`, and decisions in one batch run concurrently. A handler that prompts on a shared device serializes
  its own prompts.

### Wrappers forward the new trait methods

A type that wraps another and implements the trait itself must forward the new methods, or it
reports the trait default instead of the wrapped value.

`Tool` gains `effect()`, `origin()`, `annotations()`, and `timeout_override()`. Without
forwarding, a wrapped tool is `NonIdempotent`, its approvals bind to the `"static"` origin, and
its annotations are lost:

```rust
use std::time::Duration;
use adk_core::ToolEffect;
use serde_json::Value;

fn effect(&self) -> ToolEffect {
    self.inner.effect()
}
fn origin(&self) -> &str {
    self.inner.origin()
}
fn annotations(&self) -> Option<&Value> {
    self.inner.annotations()
}
fn timeout_override(&self) -> Option<Option<Duration>> {
    self.inner.timeout_override()
}
```

`ReadonlyContext` gains `acting_context()`. A context wrapper that does not forward it reports
the derived identity (`urn:adk:agent:{app}/{agent}`) instead of the configured principal:

```rust
use adk_core::ActingContext;

fn acting_context(&self) -> ActingContext {
    self.inner.acting_context()
}
```

`Agent` gains `screen_user_input`, which the runner calls on the root agent before it saves a
user message. Its default screens with `sub_agents()`, so an agent that runs another without
listing it as a sub-agent delegates to it:

```rust
use adk_core::{Content, Result};

async fn screen_user_input(&self, content: &Content) -> Result<Option<Content>> {
    self.inner.screen_user_input(content).await
}
```

### Instructions travel as `system` contents

`LlmAgent` sends its global instruction, instruction, and output-schema directive with role
`"system"` instead of `"user"`. A custom `Llm` implementation maps `system` contents to its
provider's system prompt.

### Run lifecycle

- **Transfers obey the source agent's restrictions.** A transfer that a tool or a custom agent
  requests is checked like the model's `transfer_to_agent` call: to a sub-agent, to the parent
  unless `disallow_transfer_to_parent`, or to a peer unless `disallow_transfer_to_peers`. Any
  other target is refused and control stays with the source; a root with
  `strict_transfer_policy()` fails the run with `agent.transfer.target_forbidden`.
- **`after_agent` runs on every exit except a failure or a held call**, including a transfer, a
  turn-ending tool result, and a cancellation, so after-agent callbacks see these exits.
  Plugins' `after_run` runs once, after the run's last event, also when the consumer drops the
  stream.
- **Input guardrails of every agent in the tree screen each user message before it is saved.**
  An input guardrail on a sub-agent, workflow step, or transfer target screens the message for
  the whole run instead of only when that agent runs, and a blocked message is not saved.
- **Runner plugins' agent, model, and tool callbacks run.** A `PluginManager` on the runner had
  only its run, user-message, and event callbacks called. Its `before_agent`, `after_agent`,
  `before_model`, `after_model`, `before_tool`, `after_tool`, and `on_tool_error` now run ahead
  of each agent's own, and a callback that returns a value short-circuits the agent's callbacks
  of that kind.
- **`adk_runner::Callbacks` is removed**, with its `BeforeModelCallback`,
  `AfterModelCallback`, `BeforeToolCallback`, and `AfterToolCallback` aliases; the runtime never
  called them. Register callbacks on the agent builder or as runner plugins.
- **`${x}`, `\{x}`, and `{{x}}` in instructions stay literal.** Only `{var}`, `{var?}`, and
  `{artifact.name}` are substituted.

### History sent to the model

- **Workflow sub-agents see other agents' turns as context.** An `LlmAgent` without transfer
  targets, such as a `SequentialAgent` step, receives another agent's text, calls, and results
  as quoted user-role context instead of as its own model turns. Code that matched the old
  request shape needs updating.
- **Calls without IDs get generated `adk-call-` IDs.** A function call a provider sends without
  an ID carries a generated ID (`adk_core::GENERATED_CALL_ID_PREFIX`) in the saved event, its
  responses, and `ToolContext::function_call_id()`, instead of `{invocation}_{name}_{index}`.
  Model requests leave the generated IDs out.
- **A model turn without an answer fails the run** with `model.empty_response`, instead of
  succeeding with no output: a final turn with no parts, only thinking, or only whitespace.
- **Model events carry one bounded copy of the request** (`trace_payload_max_bytes`, full only
  with `record_payloads`) and no `gcp.vertex.agent.llm_request` provider metadata.

## adk-agent

### Tool failures reach the model without their message

A tool that returns `Err`, or a before-tool callback that fails, is answered with the error's
component, category, and code — `{"error": "tool '<name>' failed: <component>.<category> (<code>)"}`
— instead of its message, so connection strings and upstream bodies stay out of model requests
and sessions. The message still reaches `on_tool_error` and `ToolOutcome::error`. An error with
code `tool.invalid_arguments` keeps its text.

When an after-tool callback or plugin fails after the tool ran, the call is answered with
`adk_core::result_withheld_response` (`"status": "result_withheld"`) instead of the callback's
error, so the model does not repeat the side effect.

### A failing toolset no longer fails the turn

When a toolset's `tools()` call fails, `LlmAgent` skips that toolset, logs a warning, and runs
the model with the tools that resolved. Both 2.3.0 behaviours are one builder call away:

```rust
use adk_agent::LlmAgentBuilder;

let agent = LlmAgentBuilder::new("assistant")
    .model(model)
    .toolset(toolset)
    // Fail the turn when a toolset cannot list its tools, as 2.3.0 did.
    .strict_toolsets(true)
    // Send tool error messages to the model, as 2.3.0 did.
    .expose_tool_error_messages(true)
    .build()?;
```

### Other agent changes

- **Two static tools with one name fail the build.** `LlmAgentBuilder::build`,
  `CodeActAgentBuilder::build`, and the realtime builders return `agent.duplicate_tool_name`
  instead of letting the last registration win. Rename one tool or register it once.
- **Team cost caps fail closed.** `TeamBudget::max_cost_microusd` is enforced against priced
  usage, and a response with no known cost stops the team unless `allow_unpriced_models` is set.
  Team budget errors use `ErrorCategory::ResourceExhausted` (codes `budget.*`) instead of the
  retryable `RateLimited`.

```rust
use adk_agent::TeamBudget;

let budget = TeamBudget {
    max_cost_microusd: Some(2_000_000),
    // Count a response with no known cost as free instead of stopping the team.
    allow_unpriced_models: true,
    ..TeamBudget::default()
};
```

## adk-tool and adk-rust-macros

### Tool arguments are checked against the schema

`#[tool]` validates each call against its parameters schema before the function runs, with
`additionalProperties: false` on every object that declares all its fields. An undeclared key, a
value outside a `range`, `length`, or `pattern` bound, or a missing required field fails the call
with `tool.invalid_arguments`, which the model can correct; serde used to drop unknown keys and
the bounds were never enforced. `FunctionTool` and `StatefulTool` with
`with_parameters_schema::<T>()` validate the same way. A tool that accepts input its schema does
not describe, such as a `#[serde(alias)]` key, opts out:

```rust
use adk_tool::{AdkError, tool};
use schemars::JsonSchema;
use serde::Deserialize;
use serde_json::{Value, json};

#[derive(Deserialize, JsonSchema)]
struct LookupArgs {
    /// The order to look up.
    #[serde(alias = "orderId")]
    order_id: String,
}

/// Looks up an order, accepting the legacy `orderId` key.
#[tool(lenient_args)]
async fn lookup_order(args: LookupArgs) -> Result<Value, AdkError> {
    Ok(json!({ "order_id": args.order_id }))
}
```

```rust
use adk_tool::FunctionTool;
use schemars::JsonSchema;
use serde::Serialize;

#[derive(Serialize, JsonSchema)]
struct LookupArgs {
    order_id: String,
}

let tool = FunctionTool::new("lookup_order", "Looks up an order", |_ctx, args| async move {
    Ok(args)
})
.with_parameters_schema::<LookupArgs>()
.with_lenient_args(true);
```

### MCP

`SimpleClient::inner` returns the shared connection, since requests no longer go through a mutex:

```rust
// 2.3
let peer = client.inner().lock().await.peer().clone();
```

```rust
// 3.0
let peer = client.inner().peer().clone();
```

`should_refresh_connection` takes the `rmcp::ServiceError` instead of its text, and reconnects
only on a closed transport, a broken connection, an interrupted stream, an expired session, or an
HTTP 401:

```rust
use adk_tool::mcp::should_refresh_connection;

// 2.3
let reconnect = should_refresh_connection(&error.to_string());
```

```rust
use adk_tool::mcp::should_refresh_connection;

// 3.0
let reconnect = should_refresh_connection(&error);
```

`McpServerManager` reports a server whose handshake is in progress as `ServerStatus::Starting`,
and a server that has not finished its handshake within `with_startup_timeout` (30 seconds by
default) is `FailedToStart`. Raise the timeout for a server that downloads a package on its first
start.

### AgentTool

A delegation that runs past `AgentTool::timeout` is a `Timeout` tool error in every
`AgentToolFailureMode`. Under `AgentToolFailureMode::Propagate`, a failed delegate's error keeps
its category and code instead of becoming `tool.legacy`. The delegate's `session_id()` is its
caller's session ID instead of an `agent-tool-{uuid}` ID.

## adk-model

- **Unsupported generation settings fail by name.** The OpenAI Chat Completions, OpenAI
  Responses, Anthropic, Bedrock, Groq, DeepSeek, and Azure AI Inference clients dropped
  `stop_sequences`, `seed`, `frequency_penalty`, `presence_penalty`, and `top_logprobs`. Each
  now sends the ones its API supports and fails a request that sets any other with
  `model.unsupported_config` before sending it; remove that field from the provider's
  `GenerateContentConfig`.
- **`GeminiModel`, `OllamaModel`, and OpenRouter send the same settings.** `GeminiModel` and
  `OllamaModel` now send all five. Current Gemini models (`gemini-3.5-flash-lite`,
  `gemini-3.7-flash`) answer penalties and log probabilities with `INVALID_ARGUMENT`, so a
  Gemini config that set them fails with `ErrorCategory::InvalidInput` where it ran without
  them; remove them. The Gemini Interactions transport and OpenRouter's Responses mode fail
  with `model.unsupported_config` on the fields their APIs lack (penalties and
  `top_logprobs`; `seed`). `adk_gemini::GenerationConfig` and `adk_gemini::Candidate` gain
  fields, so struct literals end with `..Default::default()`.
- **A request's `effort` wins over the client's.** `GenerateContentConfig::effort` is new; a
  request that sets it runs at that level on every client with an effort control, whatever
  the client was built with (see [Per-Call Reasoning Effort](../models/providers.md#per-call-reasoning-effort)).
  `OpenAIClient` built with reasoning effort `None` sends a GPT-5.6 tool call that sets an
  effort through the Responses API.
- **Bedrock `prompt_token_count` includes cache reads and writes**, as `AnthropicClient` reports
  it. Code that added the cache counts itself counts them twice.
- **The `openai` feature enables `async-openai`'s `byot` feature.** An application that also
  calls `async-openai` 0.41 directly sets `stream: Some(true)` on requests it passes to
  `create_stream`.
- **Groq presets for delisted models are removed.** `GroqConfig::llama8b`, `GroqConfig::mixtral`,
  `GroqConfig::gemma`, `GroqClient::llama8b`, and `GroqClient::mixtral` selected models Groq no
  longer serves. Use `GroqConfig::gpt_oss_20b`, `GroqConfig::gpt_oss_120b`, or
  `GroqConfig::new(key, model)`.
- **The Gemini Interactions allowlist names current models.** `InteractionTarget::parse` and
  `GeminiModel::use_interactions_api(true)` refuse `gemini-2.5-pro`, `gemini-2.5-flash`,
  `gemini-2.5-flash-lite`, and `gemini-3-flash-preview` with
  `model.gemini.interactions.unsupported_target`; `gemini-3.8-flash` is accepted.

## adk-session

Rewind takes the full session identity, so one user's rewind cannot truncate another user's
session with the same ID:

```rust
// 2.3
let session = sessions.rewind_steps("session-1", 2).await?;
```

```rust
use adk_core::{AdkIdentity, AppName, SessionId, UserId};

// 3.0

    UserId::try_from("user-1")?,
    SessionId::try_from("session-1")?,

```

- **`create` for an existing session fails** with `session.already_exists`
  (`ErrorCategory::Conflict`) on every backend and writes nothing. The in-memory and Redis
  backends replaced the session. Check `AdkError::is_conflict()` where a create may race.
- **`delete_all_sessions` also deletes the user's `user:` state** in the app, on every backend;
  Vertex AI implements it by deleting each session. Keep a value that must outlive the user's
  sessions in `app:` state or outside the session store. The trait's default implementation
  returns `session.delete_all.unsupported` (`ErrorCategory::Unsupported`).
- **`sql_schema_version` and `schema_version()` report read failures** as errors instead of
  version 0; they return 0 only when the registry table does not exist.
- **SQL migration steps are `'static`**: `migration::sqlite_runner::run_sql_migrations` and
  `migration::pg_runner::run_sql_migrations` take `&'static [(i64, &'static str, &'static str)]`.
  Declare custom steps as a `const` or `static` slice.
- **SQLx 0.9**: applications that share pools or call the migration runners update their SQLx
  dependency; see [SQLx 0.9 in ADK-Rust 3.0](sqlx-0.9.md).

## adk-artifact

- **Artifact versions are immutable.** A save with `version: Some(n)` for an existing `n` fails
  with `artifact.version_exists` (`ErrorCategory::Conflict`) instead of replacing it; save with

- **The session id `user` is reserved** for user-scoped artifacts and is rejected with

- **`FileArtifactService` writes a new on-disk layout**; see [before you upgrade](#before-you-upgrade).

## adk-memory and adk-rag

`PgVectorStore` accepts collection names of 1 to 59 ASCII lowercase letters, digits, and
underscores, and returns `RagError::VectorStoreError` for any other name; 2.3.0 rewrote invalid
characters to `_`, so `docs-v1` and `docs_v1` shared one table. `PgVectorStore::new` returns
`adk_rag::Result`. The SQLx and pgvector feature changes are in the
[SQLx 0.9 guide](sqlx-0.9.md).

`RagTool` (`rag_search`) answers each result as `{"id", "document_id", "text", "metadata",
"score"}` instead of the whole `SearchResult`, so embedding vectors no longer reach the model. A
`top_k` argument goes through `RagPipeline::query_with_top_k`, which reranks and applies the
similarity threshold as `query` does, and a missing `query` or a `top_k` that is not a positive
integer fails with `tool.invalid_arguments`.

## adk-graph

### ExecutionConfig has no struct literal

`ExecutionConfig` gains public fields and a crate-private one, so code outside `adk-graph`
builds it with its constructor and builder methods:

```rust
use std::collections::HashMap;
use adk_graph::node::ExecutionConfig;

// 2.3
let config = ExecutionConfig {
    thread_id: "refund-42".to_string(),
    resume_from: None,
    recursion_limit: 25,
    metadata: HashMap::new(),
    parent_context: None,
};
```

```rust
use adk_graph::node::ExecutionConfig;

// 3.0
let config = ExecutionConfig::new("refund-42").with_recursion_limit(25);
```

### The graph's recursion limit bounds its runs

`ExecutionConfig::recursion_limit` is `Option<usize>`. `None`, the default, applies the graph's
limit — 100 unless `CompiledGraph::with_recursion_limit` or `GraphAgentBuilder::recursion_limit`
sets it — and `ExecutionConfig::with_recursion_limit` overrides it for one run. 2.3.0 ignored the
graph's limit and capped every run at the `ExecutionConfig` default of 50 super-steps, so a run
that stopped at 50 now continues to the graph's limit. Code that read the field as a `usize`
reads an `Option`.

### Checkpoints carry a per-thread version

`Checkpointer::save` refuses a version that is not greater than every stored version of the
thread (`GraphError::CheckpointConflict`). A caller that saves several checkpoints on one thread
numbers them:

```rust
use adk_graph::state::{Checkpoint, State};

let first = Checkpoint::new("thread-1", State::new(), 0, vec!["plan".to_string()]);
checkpointer.save(&first).await?;
let next = Checkpoint::new("thread-1", State::new(), 1, vec![]).with_version(first.version + 1);
checkpointer.save(&next).await?;
```

A custom `Checkpointer` implements `prune`, which no longer has a default that kept everything.

### Functional resume loads the checkpoint `resume_from` names

The `#[entrypoint]`-generated `invoke` loads `ExecutionConfig::resume_from` by checkpoint id, and
fails with `GraphError::CheckpointError` when the thread has no checkpoint with that id. To resume
where a thread left off, pass the id `Checkpointer::load` returns:

```rust
use adk_graph::node::ExecutionConfig;

// 2.3
let config = ExecutionConfig::new("refund-42").with_resume_from("latest");
```

```rust
use adk_graph::node::ExecutionConfig;

// 3.0
let latest = checkpointer
    .load("refund-42")
    .await?
    .ok_or_else(|| anyhow::anyhow!("thread refund-42 has no checkpoint to resume"))?;
let config = ExecutionConfig::new("refund-42").with_resume_from(&latest.checkpoint_id);
```

### Graph checkpoints are keyed by app, user, and session

`GraphAgent` runs a session on `session_thread_id(app_name, user_id, session_id)` and `NodeTool`
runs each call on `tool_call_thread_id(app_name, user_id, session_id, function_call_id)`, instead
of the bare session id, so a user who picks another user's session id cannot resume that user's
run. Checkpoints written under a bare session id are not read. Code that loads a session's
checkpoints directly uses the new id:

```rust
// 2.3
let latest = checkpointer.load(session_id).await?;
```

```rust
use adk_graph::agent::session_thread_id;

// 3.0
let latest = checkpointer.load(&session_thread_id(app_name, user_id, session_id)).await?;
```

To keep a paused run across the upgrade, re-key its checkpoints from the bare session id to
`session_thread_id(app_name, user_id, session_id)`; otherwise the session starts over on its next
turn.

### Errors, pauses, and events

- An agent node's failure is `GraphError::AgentFailed { node, source }`, and
  `From<GraphError> for AdkError` returns the agent's own error, so a rate-limited model stays
  `RateLimited`. `GraphAgent` and `NodeTool` convert graph errors with `AdkError::from` instead
  of flattening them to `AdkError::agent` or `AdkError::tool`.
- A functional suspension is `GraphError::Suspended` and a cancellation `GraphError::Cancelled`,
  instead of `GraphError::Other`.
- `InterruptedExecution::interrupts` and `SuperStepResult::interrupts` carry every pause of a
  step, and `GraphAgent` yields one event per pause. Read a pause with
  `GraphInterruptPayload::from_event`.
- `GraphAgent` streams its agent nodes' events under the turn's invocation id, and every event it
  builds carries that id instead of `"graph_output"` or `"graph_interrupted"`.
- `SubgraphNode` threads become `<parent thread>/<node>@<step>`, and an entry of
  `{node}_fan_in` is the predecessor's own updates instead of the whole state.

## adk-server

### The server is reachable from this machine only by default

`Launcher` serve mode, `adk_cli::serve::run_serve`, and `adk-rust serve` listen on `127.0.0.1`
instead of `0.0.0.0`. An empty `SecurityConfig::allowed_origins`, the default, allows no
cross-origin access, and a request whose `Host` is not `localhost`, `*.localhost`, an IP
address, the A2A or backend URL's host, or a listed name is refused with `403`. Where the server
must be reachable from other machines, set all three:

```rust
use std::net::{IpAddr, Ipv4Addr};
use adk_cli::Launcher;
use adk_server::SecurityConfig;

let security = SecurityConfig {
    allowed_origins: vec!["https://app.example.com".to_string()],
    ..SecurityConfig::default()
}
.with_allowed_hosts(["agents.example.com"]);
Launcher::new(agent)
    .with_bind_address(IpAddr::V4(Ipv4Addr::UNSPECIFIED))
    .with_security_config(security)
    .run_serve_directly(8080)
    .await?;
```

With `ServerBuilder`, set the hosts and origins on the `ServerConfig`:

```rust
use adk_server::ServerConfig;

let config = ServerConfig::new(agent_loader, session_service)
    .with_allowed_origins(vec!["https://app.example.com".to_string()])
    .with_allowed_hosts(vec!["agents.example.com".to_string()]);
```

`vec!["*".to_string()]` as `allowed_origins` restores the previous CORS behaviour. The
`cargo-adk` `api` and `server` addons read `BIND_HOST` (default `127.0.0.1`), and the generated
Dockerfiles set `BIND_HOST=0.0.0.0`.

### A2A

A2A clients send messages only to the origin the agent card came from, and refuse a card whose
endpoint is elsewhere with `a2a.card_endpoint_refused`. Allow a further origin explicitly:

```rust
use adk_server::a2a::RemoteA2aAgent;

let agent = RemoteA2aAgent::builder("billing")
    .description("Billing agent")
    .agent_url("https://agents.example.com")
    .allow_endpoint_origin("https://rpc.example.com")
    .build()?;
```

Model thinking never reaches a peer. `v1::convert::adk_part_to_wire` returns `Option`, with
`None` for a thinking part:

```rust
use adk_server::a2a::v1::convert::adk_part_to_wire;

// 2.3
for part in parts {
    wire.push(adk_part_to_wire(part)?);
}
```

```rust
use adk_server::a2a::v1::convert::adk_part_to_wire;

// 3.0
for part in parts {
    // `None` for a thinking part, which stays private.
    if let Some(converted) = adk_part_to_wire(part)? {
        wire.push(converted);
    }
}
```

`RemoteA2aConfig`, `RemoteA2aV1Config`, `RemoteA2aAgent`, and `RemoteA2aAgentBuilder` hold an
optional credential broker, so they are no longer `UnwindSafe` or `RefUnwindSafe`.

A task that ends on a held or long-running call is `input-required`, and one that ends on an
`adk_request_credential` call is `auth-required` (the new `TaskState::AuthRequired`).

### Background runs and cron jobs use the durable stores

The `background` feature's process-local stores are removed: `RunStore`, `BackgroundRun`,
`BackgroundRunner`, `RunPersistence`, `FileRunPersistence`, `PersistedRun`, `RunRetention`,
`CronJobStore`, `CronJob`, `DEFAULT_MAX_QUEUE_DEPTH`, and `CronState::with_max_queue_depth`.
`BackgroundState` keeps runs in a `DurableRunStore` (in memory unless `with_run_store` gives it a
shared one) and `CronState` keeps jobs in a `ScheduleStore`:

```rust
use std::sync::Arc;
use adk_server::background::{
    BackgroundRunner, BackgroundState, CronState, FileRunPersistence, RunStore, WorkflowExecutor,
};

// 2.3
let store = RunStore::new().with_persistence(Arc::new(FileRunPersistence::new("runs.json")));
let runner = BackgroundRunner::new(store.clone()).with_executor(executor);
let background = BackgroundState { store, runner };
let cron = CronState::new(background.clone()).with_max_queue_depth(10);
```

```rust
use std::sync::Arc;
use adk_server::background::{BackgroundState, CronState, WorkflowExecutor};
use adk_session::{SqliteRunStore, SqliteScheduleStore};

// 3.0
let runs = SqliteRunStore::new("sqlite://runs.db?mode=rwc").await?;
runs.migrate().await?;
let schedules = SqliteScheduleStore::new("sqlite://runs.db?mode=rwc").await?;
schedules.migrate().await?;
let background =
    BackgroundState::new().with_run_store(Arc::new(runs)).with_executor(executor);
let cron = CronState::new(background.clone()).with_schedule_store(Arc::new(schedules));
```

- `SubmitRunRequest::timeout_secs` is removed; use `DurableWorkerConfig::run_timeout`.
  `SubmitRunRequest` gains `target`, `session_id`, `user_id`, `idempotency_key`,
  `concurrency_key`, `on_conflict`, and `not_before`, and `CreateCronJobRequest` gains
  `timezone` and `missed_fire_policy`.
- `CronState::cron_store` is now `schedules`, and `validate_cron_expression` returns
  `Result<(), String>`.
- REST responses change: `RunStatusResponse` adds `target`, `attempt`, `maxAttempts`,
  `cancelRequested`, `sessionId`, and `checkpoint`; `CronJobResponse` uses the job name as
  `jobId` and drops `createdAt`, `lastExecution`, `executionCount`, and `activeRunCount`.
  Creating a job with an existing name returns `409`, and `DELETE /runs/{id}` on a running run
  returns it `running` with `cancelRequested: true` until its worker stops it.

## adk-guardrail

- **Guardrail blocks are structured errors.** An input or output block ends the run with
  `ErrorComponent::Guardrail`, `ErrorCategory::InvalidInput` (HTTP 400), and code
  `guardrail.input_blocked` or `guardrail.output_blocked`, instead of `agent.legacy` (HTTP 500).
  Code that matched `agent.legacy` or `is_agent()` for a block matches the new codes.
- **`PathAllowList` denies a call that omits a path argument**, which it allowed unchecked.
- **`PathAllowList` checks the keys it names at any depth**, in nested objects and arrays, not
  only at the top level. A call holding a path outside the allowed roots, or a value other than a
  path, under a named key anywhere in its arguments is denied. Scope the guardrail with `on_tools`
  when a tool uses a key of the same name for something other than a filesystem path.
- **`ContentFilter::new` and `ContentFilter::blocked_keywords` return `Result`**, failing with
  `GuardrailError::Regex` for a keyword list that cannot compile instead of building a filter
  that blocks nothing.

```rust
use adk_guardrail::{ContentFilter, PathAllowList};

let filter = ContentFilter::blocked_keywords(vec!["internal-only".to_string()])?;
// Allow calls that omit the path arguments, as 2.3.0 did.
let paths = PathAllowList::new("workspace", ["path"], ["/srv/data"]).allow_missing();
```

`Evaluator::evaluate_cases_parallel` returns a `Result`, failing for a concurrency of 0 or an

- **Judged criteria fail closed.** A judge reply without a valid `SCORE:` line is an error, and

## adk-payments

`PaymentPolicyGuardrail::evaluate` and `PaymentPolicySet::evaluate` are async and take a
`PaymentPolicyContext`, which carries the operation, the paying org and agent, and the spend
ledger:

```rust
use adk_payments::domain::{ProtocolDescriptor, TransactionRecord};
use adk_payments::guardrail::{PaymentPolicyDecision, PaymentPolicyGuardrail};

// 2.3
impl PaymentPolicyGuardrail for NoTestMerchant {
    fn name(&self) -> &str {
        "no_test_merchant"
    }

    fn evaluate(
        &self,
        record: &TransactionRecord,
        _protocol: &ProtocolDescriptor,
    ) -> PaymentPolicyDecision {
        if record.merchant_of_record.merchant_id == "test" {
            return PaymentPolicyDecision::deny(Vec::new());
        }
        PaymentPolicyDecision::allow()
    }
}
```

```rust
use adk_payments::domain::{ProtocolDescriptor, TransactionRecord};
use adk_payments::guardrail::{
    PaymentPolicyContext, PaymentPolicyDecision, PaymentPolicyGuardrail,
};
use async_trait::async_trait;

// 3.0
#[async_trait]
impl PaymentPolicyGuardrail for NoTestMerchant {
    fn name(&self) -> &str {
        "no_test_merchant"
    }

    async fn evaluate(
        &self,
        record: &TransactionRecord,
        _protocol: &ProtocolDescriptor,
        _context: &PaymentPolicyContext,
    ) -> PaymentPolicyDecision {
        if record.merchant_of_record.merchant_id == "test" {
            return PaymentPolicyDecision::deny(Vec::new());
        }
        PaymentPolicyDecision::allow()
    }
}
```

Payment tools enforce their declared scopes. `PaymentToolsetBuilder::build` wraps every tool in
an `adk-auth` `ScopeGuard`, which reads `ToolContext::user_scopes()` by default; grant the
scopes, or supply a resolver:

```rust
use adk_auth::{ScopeGuard, StaticScopeResolver};
use adk_payments::tools::PaymentToolsetBuilder;

let toolset = PaymentToolsetBuilder::new(checkout, transactions)
    .with_scope_guard(ScopeGuard::new(StaticScopeResolver::new(vec![
        "payments:checkout:create",
        "payments:checkout:update",
        "payments:checkout:complete",
    ])))
    .build();
```

- **Payment tools govern checkouts.** Checkout creation and completion go through
  `GovernedCheckoutService`: a policy escalation fails with `payments.policy.approval_required`
  unless the run approves the call, and completion fails with
  `payments.policy.checkout_not_found` when the backend cannot return the checkout.
- **The acting agent is the commerce actor.** The tools record the acting agent's id
  (`urn:adk:agent:{app}/{agent}` unless configured) instead of `agent-tool`.
- **`auth::PaymentOperation` gains `ExecutePayment`**, with the scope `payments:payment:execute`.
- **Autonomous AP2 payments need a verified intent authorization**: submit the intent mandate
  with its user authorization artifact.

## adk-realtime

- `RealtimeAgent`, `RealtimeRunner`, `IntegratedRealtimeRunner`, and `ToolBridgeAdapter` answer
  a failed tool without its message; call `expose_tool_error_messages(true)` on the builder, or
  `ToolBridgeAdapter::with_exposed_error_messages(true)`, for the 2.3.0 behaviour.
- A failed after-tool stage answers with `result_withheld_response` instead of the tool's result
  or the callback's error.
- Tool-call arguments that are not valid JSON are answered with an error instead of running the
  tool with `{}`.
- Two static tools with one name fail the build.

## adk-browser

Navigation refuses loopback, private, link-local, shared-address, and cloud metadata addresses,
host names that resolve to them, and host names the agent host cannot resolve, and checks the
page the browser ends on after a redirect. `browser_file_upload` is in no profile and uploads
only inside configured roots. For an agent meant to reach an internal network or upload files:

```rust
use adk_browser::{BrowserSession, BrowserToolset};

// Only for an agent meant to browse an internal network and upload files.
let toolset = BrowserToolset::new(browser)
    .with_private_network_access(true)
    .with_file_upload(["/srv/agent/uploads"]);
```

`with_unresolved_hosts(true)` permits host names the agent host cannot resolve, for a browser
that resolves names through a proxy.

## adk-devtools

`Workspace::new` disables `bash`, which runs model-written commands outside the file tools'
path containment, and `DevToolset` omits the tool until it is enabled. A model-supplied
`timeout_secs` can no longer extend a command past `Workspace::bash_timeout`.

```rust
use adk_devtools::{DevToolset, Workspace};

let toolset = DevToolset::new(Workspace::new("./my-repo").allow_bash(true));
```

## adk-code and adk-sandbox

`ContainerConfig` and `DockerConfig` drop every capability, set `no-new-privileges`, and limit a
container to 256 processes by default. A `DockerConfig` setup command that switches users, such
as `apt-get`, needs the capabilities:

```rust
use adk_code::DockerConfig;

let docker = DockerConfig {
    image: "python:3.12-slim".to_string(),
    setup_commands: vec!["apt-get update && apt-get install -y git".to_string()],
    // `apt-get` switches users, which needs the capabilities kept.
    drop_capabilities: false,
    ..DockerConfig::default()
};
```

`SandboxError` is `#[non_exhaustive]`, so a `match` on it needs a wildcard arm.

## adk-managed

- A custom tool call ends the turn with `agent.custom_tool_use` and a `status.idle` that
  requires action; the turn continues after `user.custom_tool_result`. `ToolParkingLot` and the
  `parking` module are removed, and `SessionLoop::new` and `SessionLoop::with_pause_controls` no
  longer take a parking lot.
- `DefaultModelResolver` is no longer a unit struct; build it with
  `DefaultModelResolver::new()`.

`ManagedSessionState` gains `record`, `pending`, and `durable_run_id`; build it with its
constructor:

```rust
use adk_managed::{ManagedSessionState, RunState};

let state = ManagedSessionState::new(Vec::new(), RunState::initial());
```

`ScriptedLlm` is `adk_model::ScriptedLlm`. A call past the last scripted turn fails with
`model.scripted.exhausted`, and the turn counters are replaced:

```rust
use adk_managed::{ScriptedLlm, ScriptedTurn};

// 2.3
let llm = ScriptedLlm::new(
    "scripted-model",
    vec![ScriptedTurn { text: Some("Done.".to_string()), tool_calls: vec![] }],
);
let calls = llm.turns_consumed();
let left = llm.total_turns() - calls;
```

```rust
use adk_managed::{ScriptedLlm, ScriptedTurn};

// 3.0
let llm = ScriptedLlm::new(
    "scripted-model",
    vec![ScriptedTurn { text: Some("Done.".to_string()), tool_calls: vec![] }],
);
let calls = llm.requests().len();
let left = llm.remaining();
```

## adk-acp

`adk-acp` moves to `agent-client-protocol` 3.3 (ACP schema 1.11). Code that uses the
`adk_acp::agent_client_protocol` re-export follows the SDK's
[3.0 migration notes](https://github.com/agentclientprotocol/rust-sdk/blob/main/src/agent-client-protocol/CHANGELOG.md).
The ACP wire protocol stays at version 1.

## adk-awp

`InMemoryEventSubscriptionService` delivers events over HTTP with Standard Webhooks signatures,
and refuses a subscription whose callback URL names a loopback, private, or link-local address.
An in-cluster receiver needs a delivery that allows private networks:

```rust
use adk_awp::events::InMemoryEventSubscriptionService;
use adk_core::webhook_delivery::{EgressPolicy, WebhookDelivery};

let subscriptions = InMemoryEventSubscriptionService::new().with_delivery(
    WebhookDelivery::new().with_egress_policy(EgressPolicy::allow_private_networks()),
);
```

## adk-retry-reflect

`RetryTracker` keeps counts per invocation, so its methods take the invocation ID, the tool name,
and the call key:

```rust
use adk_retry_reflect::RetryTracker;

// 2.3
let mut tracker = RetryTracker::new();
let attempts = tracker.increment("search:call-1");
let total = tracker.total();
```

```rust
use adk_retry_reflect::RetryTracker;

// 3.0
let mut tracker = RetryTracker::new();
let attempts = tracker.increment("invocation-1", "search", "call-1");
let total = tracker.total("invocation-1");
```
